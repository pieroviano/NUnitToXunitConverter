# MsTestsToNunit.Tests

Test project inside **MsOrNUnitToXunitConverter**, a Roslyn-based command-line tool that rewrites MSTest/NUnit
test sources into xUnit in place, one `.csproj` at a time, taking a restorable backup first.

It is an xUnit project covering the *text* transforms in
[`Net4x.ConversionClassLibrary`](https://github.com/pieroviano/NUnitToXunitConverter/tree/master/ConversionClassLibrary)
— the MSTest-to-NUnit string and regex rewrites. It does not cover
[`Net4x.ProjectsLibrary`](https://github.com/pieroviano/NUnitToXunitConverter/tree/master/ProjectsLibrary);
that has its own test project, `MsOrNUnitToXunitConverter.Tests`.

**Not a NuGet package.** The csproj sets `IsPackable=false` and `GeneratePackageOnBuild=False`. It also
declares `PackageReadmeFile` and packs this file with a `None Include="README.md" Pack="true"` item, but
those are copy-pasted from the two packable projects and are inert while `IsPackable` is `false`. There is no
install command.

- Target framework: `net8.0-windows`; the repository as a whole needs the .NET 10 SDK to build.
- References: `Net4x.XunitTests` (xUnit), `Microsoft.NET.Test.Sdk`, `Net4x.StandardTypesWrappers`,
  `Net4x.NuGetUtility` (`PrivateAssets="All"`, with two `Import` elements pulling its `NuGet.Utility.props`
  and `.targets`), and a `ProjectReference` to `ConversionClassLibrary`.
- `GlobalUsings.cs` contains a single `global using Xunit;`.

## What is covered

All tests exercise `ConversionClassLibrary.MsTestToNUnitContent` directly (`new MsTestToNUnitContent()`),
with no mocks and no file system access.

| File | Subject |
| --- | --- |
| `FormatContentTests.cs` | `FormatContent(string)` — Roslyn `Formatter.Format` re-indentation of a badly formatted class, compared against the expected string stored in `Resources.resx` (`Resources.FormatContentTests_FormatContent_Formats_Content_With_Indentation_`). The comparison normalises `\r\n` to `\n`, because `FormatContent` returns LF-only text. |
| `TransformMethodsTests.cs` | `TransformMethods(string)` — the `[TestMethod, ExpectedException(typeof(XException))]` → `[Test]` + `try { … Assert.Fail(); } catch (XException e) { Console.WriteLine(e); }` regex rewrite. One positive case (asserts the generated `catch (TaskCanceledException e)` appears) and one negative case, where a plain `[TestMethod]` produces no try/catch — line endings are still normalised to LF, which `TransformMethods` does unconditionally. |

`Resources.resx` / `Resources.Designer.cs` hold only that one expected-output string; the designer file is
generated by `ResXFileCodeGenerator` and should not be edited by hand.

Only the happy shape of the `TransformMethods` regex is exercised. It matches solely when `[TestMethod]` and
`[ExpectedException]` share one bracket list in that order (separate lines do not match), when the exception
type name is unqualified and ends in `Exception` (`typeof(System.TaskCanceledException)` is missed), and when
the method is exactly `public void Name()` — no parameters, no `async Task`, no other modifiers.

`string? Transform(string fileContent, bool format = true)` — the `[TestClass]` / `[TestMethod]` /
`Assert.ThrowsException` replacement pass, which returns `null` when nothing in the input changed — has no
test here.

## Running the tests

`Net4x.XunitTests` declares `xunit.runner.visualstudio` with `exclude="Build,Analyzers"`, which strips the
VSTest adapter's build assets. A plain `dotnet test` therefore reports *"No test is available"*, and
`--test-adapter-path` does not help. Copy the adapter into the output directory after building:

```bash
dotnet build MsTestsToNunit.Tests/MsTestsToNunit.Tests.csproj
cp "$HOME/.nuget/packages/xunit.runner.visualstudio/3.1.5/build/net8.0/xunit.runner.visualstudio.testadapter.dll" \
   MsTestsToNunit.Tests/bin/Debug/net8.0-windows/
dotnet test MsTestsToNunit.Tests/MsTestsToNunit.Tests.csproj --no-build
```

Note that the build step also builds the referenced `ConversionClassLibrary`, which has
`GeneratePackageOnBuild=True` and `PackageOutputPath=$(SolutionDir)Packages/`. `Packages` is a symlink to a
machine-wide local NuGet feed registered as the `Local` source in `NuGet.config`, so building this test
project publishes a fresh `Net4x.ConversionClassLibrary` nupkg into a feed shared with other repositories,
at a version that changes daily.

Visual Studio's Test Explorer discovers and runs the tests without the adapter copy.

## House convention in the sibling projects

This does not apply to the code under test — no type in `ConversionClassLibrary` performs file I/O or
logging, and neither test file touches the file system — but it is what the rest of the repository looks
like. `Net4x.StandardTypesWrappers` injects global usings that alias BCL static types to **interfaces**:
`File` → `System.IO.IFile`, `Path` → `System.IO.IPath`, `Directory` → `System.IO.IDirectory`,
`Console` → `System.IConsole`. So in `ProjectsLibrary` and in the CLI, `File.ReadAllText(x)` is an *instance*
call on an injectable property declared as
`public File File { get; set; } = System.IO.InputOutput.Instance.File;`, genuinely static members are fully
qualified (`System.IO.Path.DirectorySeparatorChar`), and `MsOrNUnitToXunitConverter.Tests` mocks those
properties directly with NSubstitute. Logging in those projects goes through
`LoggerFactoryContainer.Instance.LoggerFactory` (`Net4x.BaseTypes`), which the host is expected to configure.
